## 1. Software Engineering

> **Software Engineering:** systematic approach to **software development, deployment and maintenance** using engineering principles.

Mainly deals with software that is:

- **Large & complex**
    
- Developed by **teams**
    
- Long-lived and **evolving**
    
- Frequently **modified**
    

**Goal:** produce **quality software** while controlling **cost and time**.

---

## 2. Process vs Product

- **Process** → _how_ software is developed.
    
- **Product** → _what_ is produced.
    

> The **quality of the process influences the quality of the product**.

---

## 3. Software Crisis

As software systems became larger and more complex, projects often suffered from:

- **Cost overruns**
    
- **Schedule overruns**
    
- **Low quality**
    
- Failure to meet **requirements**
    

→ This led to the development of **Software Engineering** as a discipline.

---

## 4. Software Today

Software is often a **component of a larger system** (cars, smartphones, IoT, industry, etc.).

→ It must be engineered **together with the rest of the system**.

Software is also a key part of modern products and services.

---

## 5. What is Software?

Software ≠ just source code/executable.

> **Software = all artefacts associated with a software product.**

Examples:

`Source code + executable + documentation + analysis/design + tests + makefiles + ...`

---

## 6. Software Development

Main activities:

**Analysis → Design → Development → Deployment → Maintenance**

> Software development includes the **analysis, design, development, deployment and maintenance** of a software product.

---

## 7. Traditional Engineering vs Software Engineering

### Traditional Engineering

- Problems are usually **known and recurring**.
    
- Reuse of existing solutions.
    
- Strong focus on **detailed design**.
    
- Design is generally **frozen before production**.
    
- Requirements are expected to remain stable.
    
- Standard procedures are commonly followed.
    
- Strong attention is paid to analysing possible failures.
    

### Software Engineering

Software is often:

- **Complex**
    
- **Innovative**
    
- Based on problems that may not be fully understood.
    
- Subject to **continuous change**.
    

→ Completely freezing requirements is often **unrealistic**.

Software requirements may need to change **even shortly before release**.

---

## 8. Why is Software Engineering Difficult?

Software Engineering is a **young discipline**.

Unlike mature engineering disciplines:

- There are limited theories for completely verifying software before production.
    
- Development methodologies are not universally established.
    
- Software defects are not always analysed enough to prevent recurrence.
    

→ Applying traditional engineering techniques directly to software is **not straightforward**.

---

## 9. Software vs Hardware

|Hardware|Software|
|---|---|
|Manufactured|**Developed**|
|Wears out physically|**Does not wear out**|
|Harder to modify|**Highly malleable**|

> Software does not physically wear out, but it can require **continuous maintenance and evolution**.

→ Traditional hardware failure models do not directly apply to software.

---

## 10. Software Development as a Creative Activity

Software development is different from **mass production**:

- Software is **developed once** and then replicated at negligible cost.
    
- Development is essentially a **cooperative design activity**.
    
- Developers are **designers**, not factory workers.
    
- Developer **skill and creativity** are fundamental to success.
    
- Knowing techniques, tools and technologies is a **precondition**, but does not guarantee success.
    

---

## 11. Software Development as a Cooperative Activity

Non-trivial software is normally developed by a **team**.

Projects may involve:

- Multiple developers
    
- Teams distributed across different locations
    
- **Cooperation and collaboration**
    
- **Planning and control**
    

Problems can be:

- **Technical**
    
- **Organisational**
    
- **Sociological**
    

---

## 12. Software Business Models

Common models presented in the course:

- **Open source** → source code is public and everyone can contribute.
    
- **Community sourcing** → the owner allows others to contribute.
    
- **Freeware + Pro version** → basic version is free; professional version is paid.
    
- **Shareware** → free trial; payment required for continued use.
    
- **Adware** → free software supported by advertising.
    
- **Application Service Providing (ASP)** → software runs on the provider's machine; users pay to use it.
    

---

## 13. Software: Product & Process

The objective of Software Engineering is to develop a software **product** with the desired quality.

- **Product** → _what_ we want to obtain.
    
- **Process** → _how_ we obtain it.
    

> **Process quality influences product quality.**

Quality must be considered **throughout the entire process**:

- Quality is progressively **added** to the product.
    
- Product quality is continuously **checked**.
    

---

## 14. Programmer vs Software Engineer

### Programmer

- Develops a **complete program**.
    
- Starts from **specifications provided by others**.
    
- May work **individually**.
    

### Software Engineer

- **Analyses problems and application domains**.
    
- Identifies **requirements** and develops specifications.
    
- Designs potentially **reusable components**.
    
- Works as part of a **team**.
    

---

# Exam Essentials

- **Software Engineering** → systematic development, deployment & maintenance.
    
- **Process** = how | **Product** = what.
    
- **Process quality → Product quality**.
    
- Software is **more than code**.
    
- **Software Crisis** → cost, time, quality & requirements problems.
    
- Software **changes continuously** → requirements cannot always be frozen.
    
- Software is **developed, not manufactured** and **does not wear out**.
    
- Software development is a **creative + cooperative design activity**.
    
- Software projects involve **technical, organisational and sociological** problems.
    
- Software has different **business models** (open source, shareware, adware, ASP...).
    
- **Programmer ≠ Software Engineer** → the latter also analyses requirements, domains, architecture/components and teamwork.
    
- **Complexity + Criticality + Size** → need for a systematic approach.
    
- Goal → **quality + control of cost and time**.
